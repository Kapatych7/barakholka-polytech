# ADR 0002 — Стек технологий

**Статус:** принято · **Дата:** 29.09.2026 · **Задача WEEEK:** #23

## Решение

| Слой | Технология | Почему |
|---|---|---|
| Мобильный клиент | **Kotlin + Android SDK**, MVVM, Retrofit/OkHttp, Coroutines, Coil | У команды есть опыт Android-разработки (курс по Android/XML); нативный клиент — самый предсказуемый путь для MVP |
| Backend | **Python 3.12 + FastAPI** | Быстрый старт, мало шаблонного кода; Swagger/OpenAPI генерируется автоматически и служит контрактом для клиента и основой для API-тестов |
| ORM и миграции | **SQLAlchemy 2 + Alembic** | Схема БД под контролем версий, изменения — только миграциями |
| Валидация | **Pydantic v2** | Встроена в FastAPI, проверка входных данных из коробки |
| Авторизация | **JWT** (Bearer-токен), пароли — **bcrypt** | В MVP регистрация по email/паролю (по утверждённой структуре БД); вход через ЛК Политеха — в плане-максимуме |
| База данных | **PostgreSQL 16** | Заложена в утверждённой структуре БД (триггер на plpgsql) |
| Хранение фото | Файлы на сервере / S3-совместимое хранилище (MinIO), в БД — `image_url` | Соответствует таблице `Ad_Images` |
| Чат (MVP) | REST + периодический опрос | Проще в реализации; WebSocket (встроен в FastAPI) — в плане-максимуме |
| Инфраструктура | **Docker Compose**, **GitHub Actions** | Одна команда поднимает окружение у любого участника; автотесты на каждый PR |
| Тестирование | pytest (backend), Swagger / Postman (ручное API-тестирование) | |
| Дизайн, задачи | Figma, WEEEK | Уже используются командой |

## Рассмотренные альтернативы

- **Spring Boot / Ktor (Kotlin) для backend** — один язык с клиентом, но больше шаблонного кода и дольше старт.
- **Flutter** вместо нативного Android — даёт iOS «бесплатно», но у команды нет опыта Dart; вернёмся к вопросу, если iOS станет обязательным.
