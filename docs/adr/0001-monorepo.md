# ADR 0001 — Один репозиторий (monorepo) для backend и mobile

**Статус:** принято · **Дата:** 29.09.2026 · **Задача WEEEK:** #25

## Контекст

Проект «Барахолка Политех» состоит из мобильного клиента (Android) и серверного API. Код пишут двое разработчиков (frontend и backend), ещё двое участников работают с документацией, дизайном и тестированием. Срок — один семестр.

Рассматривались варианты:
1. Один общий репозиторий (monorepo) с папками `backend/` и `mobile/`.
2. Два раздельных репозитория: `barakholka-backend` и `barakholka-mobile`.

## Решение

Используем **один репозиторий** со структурой `backend/`, `mobile/`, `docs/`, `infra/`.

## Обоснование

- **Общий API-контракт.** Изменение эндпоинта на сервере и его использование в клиенте можно сделать и проверить одним Pull Request — версии не разъезжаются.
- **Маленькая команда.** Преимущества раздельных репозиториев (независимые релизы, разные права доступа, отдельные команды) при 2 разработчиках не нужны, а накладные расходы (два набора веток, синхронизация, две настройки CI) — реальные.
- **Одно место для всего.** Документация, диаграммы, отчёты по ЛР и код лежат вместе; аналитику и тимлиду не нужно следить за несколькими репозиториями.
- **Единые правила.** Одни и те же правила веток, коммитов и PR для всей команды.

## Последствия

- CI разделён по путям: `.github/workflows/backend.yml` срабатывает только на изменения в `backend/`, `mobile.yml` — только в `mobile/`.
- Android Studio открывает папку `mobile/` как отдельный проект — на работу frontend-разработчика это не влияет.
- Если в будущем появится iOS-клиент или веб-админка, они добавляются соседними папками.
